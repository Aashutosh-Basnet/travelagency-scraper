Technical Architecture & Code Guide

Full-Stack Blog Platform ("Editorial")

A comprehensive breakdown of the Express backend, MongoDB session authentication, REST APIs, and React Vite frontend.

1. Architecture Overview

The project is a decoupled full-stack publishing web application built with a modern Express backend and a React (Vite) frontend. Authentication is managed using MongoDB-backed persistent sessions (via express-session and connect-mongo), paired with bcrypt password hashing.

Key Architectural Decisions:

  • Session Authentication vs JWT: Sessions are stored server-side in MongoDB. Only the userId is stored in the session record. Sensitive data (passwords/hashes) is never stored in session state.
  • Cookie Security: Cookies use httpOnly: true to prevent XSS theft, with sameSite: 'lax' for seamless first-party transmission.
  • Image Uploads: Multer handles multipart file uploads directly to the server's uploads/ directory with file-type validation.
  • Single-Origin Tunneling (ngrok / localtunnel): Vite's development proxy routes /api and /uploads to port 5000, eliminating third-party cookie restrictions when sharing publicly.

2. Backend Implementation Deep-Dive

2.1 Server Bootstrap (server/server.js)

The main Express application connects to MongoDB, sets up trust proxy headers, enables CORS for local and tunneled domains, and attaches the MongoDB session store:

  • app.set('trust proxy', 1): Informs Express that it sits behind a reverse proxy (Vite / ngrok / localtunnel), allowing secure cookies to be transmitted accurately.
  • connect-mongo: Automatically synchronizes active sessions with the sessions collection in MongoDB so sessions persist across server restarts.
  • express.static('/uploads'): Publicly serves uploaded cover images at /uploads/:filename.

2.2 Data Models (server/models/)

Model Fields Description
User.js name, email (unique, lowercase), passwordHash, createdAt Represents user accounts. Includes regex email validation and indexed unique emails.
Post.js title, content, author (ObjectId ref to User), tags, coverImage, status ('draft' | 'published') Represents stories. Contains compound indexes on (author, createdAt) and (status, createdAt) for high-performance querying.

2.3 Authentication Controller (server/controllers/authController.js)

  • signup: Validates name, email, and password. Hashes the password with bcrypt.hash(password, 10). Creates the user in MongoDB and sets req.session.userId = user._id.
  • login: Finds the user by normalized email. Compares the plain password against the stored hash via bcrypt.compare(). On success, writes req.session.userId.
  • logout: Calls req.session.destroy() and invokes res.clearCookie('connect.sid') to erase the session ID cookie from the browser.
  • getMe: Checks req.session.userId. If present, queries MongoDB for the user with .select('-passwordHash') to ensure password hashes are never exposed.

2.4 Post CRUD Controller (server/controllers/postController.js)

  • getPublicFeed: Returns published articles ({ status: 'published' }) across all users. Populates author name and email. Supports search keywords and tag filters.
  • getUserPosts: Strictly queries articles belonging to the current user ({ author: req.session.userId }). Users never see other users' private drafts.
  • createPost: Creates a new post attached to req.session.userId, processing optional cover images via Multer.
  • updatePost & deletePost: Verifies ownership with post.author.toString() === req.session.userId.toString(). If a different user attempts to update or delete, the backend rejects the request with 403 Forbidden.

3.2 Context State Management

  • AuthContext.jsx: Calls GET /api/auth/me when the app loads. Maintains user, loading, and exposes login(), signup(), and logout().
  • ThemeContext.jsx: Tracks Dark vs Light theme, writes to localStorage, and dynamically adds/removes the .dark class on the HTML root.
  • ToastContext.jsx: Provides instant feedback toasts (toast.success(), toast.error(), toast.info()) with auto-dismiss animations.

4. Security & Best Practices

  • Password Hashing: Uses bcrypt with 10 salt rounds to defend against rainbow table attacks.
  • Zero Credential Leakage: Password hashes are stripped before returning user objects to the client.
  • Strict Ownership Enforcement: Every mutate operation (update/delete) enforces that the logged-in user is the document's author.
  • Input Validation: Validates email formats, password lengths, and required post fields on both client and server layers.
  • File Upload Restrictions: Multer enforces a 5MB size limit and strictly validates MIME types for JPEG, PNG, WebP, and GIF images.

5. Sharing over ngrok & localtunnel

When tunneled through ngrok (ngrok http 5173) or localtunnel (npx localtunnel --port 5173):

  1. External traffic enters through the public HTTPS URL (e.g. https://xyz.ngrok-free.app).
  2. Vite receives the request and relays API calls (/api/*) locally to Express on port 5000.
  3. Because client-to-API requests occur under the same public origin, browsers treat session cookies as first-party, avoiding third-party cookie blocking.
