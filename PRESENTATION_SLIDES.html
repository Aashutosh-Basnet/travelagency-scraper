🎯 Project Overview

Problem Statement & Goals

Building a secure, minimalist, distraction-free publishing platform for technical creators.

Key Challenges Addressed
  • JWT Invalidation Risks: Stateless tokens are difficult to revoke upon logout without token blocklists.
  • Bloated & Cluttered UIs: Many blogging tools use heavy shadows, excessive gradients, and confusing menus.
  • Data Leaks: Ensuring strict user-level author isolation so private drafts remain protected.
Core Architecture Goals
  • Persistent MongoDB Sessions: Real server-side session revocation with automatic expiry.
  • Dark Modern Minimalist Design: Obsidian dark surfaces, neon accents, and Plus Jakarta Sans typography.
  • Rich Authoring & Reading: Live markdown preview, drag-and-drop cover banner, and floating TOC.

🔐 Security & Auth

Session Authentication & bcrypt

Secure session cookies backed by MongoDB rather than fragile localStorage JWTs.

How Session Lifecycle Works
  • Signup / Login: Password is salted & hashed via bcrypt (10 rounds). Session initiates with req.session.userId.
  • Cookie Delivery: An encrypted connect.sid cookie is sent with httpOnly: true to stop XSS theft.
  • Logout: Calls req.session.destroy() and instantly purges the MongoDB session record and cookie.
The requireAuth Middleware
const requireAuth = async (req, res, next) => {
  if (!req.session?.userId) {
    return res.status(401).json({ message: 'Login required' });
  }
  req.user = await User.findById(req.session.userId);
  next();
};

📡 REST API

Post Management & Feed APIs

Strict ownership validation and optimized public feed retrieval.

Public Endpoints (Open Access)
  • GET /api/posts/public — Returns all published stories populated with author name & email.
  • GET /api/posts/public/:id — Public reader view for individual published stories.
  • Filters: Full search query & tag filtering parameters.
Protected Endpoints (requireAuth)
  • GET /api/posts — Returns ONLY the logged-in user's drafts & posts.
  • POST /api/posts — Creates a new post with Multer cover upload.
  • PUT & DELETE /api/posts/:id — Enforces strict author ownership (returns 403 Forbidden for others).

🌐 Public Sharing

Instant Sharing with ngrok & localtunnel

Zero-config tunnel relaying with first-party cookie preservation.

Why Single-Port Tunneling Works Best
  • Only port 5173 is tunneled: Vite proxies /api and /uploads internally to port 5000.
  • No 3rd-Party Cookie Blocking: All API calls share the same public domain (e.g. https://xyz.ngrok-free.app).
  • Express Trust Proxy: app.set('trust proxy', 1) ensures secure HTTPS headers are recognized.
One-Command Launch
# Option A: localtunnel (Zero setup)
npm run share

# Option B: Official ngrok
ngrok http 5173
